### 2.2 主枢纽流程

**入口**: `app/page.tsx` → `Home` 组件

1. 加载存档（localStorage `garden-of-shadows.save.v2`）
2. 若 URL 参数 `?visualTest=1` 且开发模式 → 跳过存档，直接进入对应章节
3. 默认视图 `"hub"`，渲染案卷目录

**菜单项**:
- `01` — 继续/开始（根据存档状态显示不同文案）
- `02` — 从头测试第二章
- `03` — 从序章重新开始
- `04` — 长线规划
- `05` — 系统设置

### 2.3 章节切换逻辑

```
继续按钮逻辑 (continueCurrentInvestigation):
  ├── west-corridor-loop → startChapterOne()
  ├── north-tower-ledger → startNorthTower()
  ├── missing-room → startMissingRoom()
  └── 其他 → startOnboarding()

每个 start* 函数:
  1. 检查是否已在对应章节 + 无完成状态 + 锚点有效
  2. 若需要，创建新的 CheckpointState
  3. 调用 persist() → setSave + storeCampaignSave
  4. setView 切换到对应运行时
```

### 3.7 完整剧情线

**序章 — 雨夜**:
- 背景：赵映受命调查听雨轩
- 触发：到达听雨轩大门，捡起三件证物（雨伞、鞋子、账册）
-  anomalies：发现不可能的墙壁（空间矛盾）
- 门的选择：三种记忆路径（视觉记忆 / 文字证词 / 空间感知）
- 冲突：与管家对峙，得知"你不是第一个来的人"
- 结局：通过大门，进入 A 区

**第一章 — A 区回廊闭环**:
- 背景：进入听雨轩 A 区，调查夫人与园丁的冲突证词
- 空间矛盾 1 (waterline-direction)：夫人记得墙脚只有墙，园丁记得有水路
- 空间矛盾 2 (corridor-count)：漏窗数量不一致，园丁记得的路形成闭环
- 借景机制：借用夫人证词中的月洞门，借用园丁记忆中的空间结构
- 追逐：无面园主出现，沿走廊逃跑
- 逃脱：切到夫人证词，通过东侧月洞门进入 B 区

**第二章 — B 区北楼证词**:
- 背景：调查北楼的三层记忆
- 证物 1：第六只茶杯（夫人 vs 账房）
- 证物 2：离开记录（账房修改的时间）
- 证物 3：画师视角的画作（雨中人物）
- 证物 4：第五个人的门板
- 推理：三个记忆层各提供一部分证据链

**第三章 — 缺失房间**:
- 背景：重构被从园林记忆中删除的房间
- 机制：四层记忆共同拼凑房间结构
- 最终揭示：玩家自己的房间 — 赵映曾经住在这里

**第四至六章（规划中）**:
- Ch4 (deleted-person)：被删除的人
- Ch5 (you-did-not-return)：你没有回来
- Ch6 (finale)：终章

## 4. 任务系统

### 4.1 任务定义架构

```typescript
// types.ts
interface ObjectiveDefinition {
  id: string;
  title: string;
  description: string;
  completionFlags: string[];      // 完成后设置的旗标
  steps: ObjectiveStep[];         // 步骤列表
}

interface ObjectiveStep {
  id: string;
  instruction: string;
  targetPosition?: [number, number, number];
  targetInteractableId?: string;
  guidance: GuidanceType[];       // 引导层级
  hints: string[];                // 按时间解锁的提示
}
```

**引导层级** (GuidanceType): `objective` | `direction` | `world-marker` | `outline` | `light` | `audio`

**提示解锁时间** (`ObjectiveDirector.ts`):
- 20 秒 → 距离提示
- 45 秒 → 语音提示
- 90 秒 → 完整提示

## 5. 调查系统（重点）

### 5.1 调查机制概览

```
调查触发: 玩家按 F 键
  └── InteractionController.raycast()
        ├── 标准证据范围: 2.35m
        ├── 序章证据范围: 2.15m
        └── NPC 范围: 2.4m
  └── 命中交互层 (layer 7)
  └── 触发 InvestigationEvent
```

### 5.2 认知切换系统

**引擎**: `CognitionController.ts` + `MechanicsOrchestrator.ts`

**认知层映射**:
```
MemoryId          →    CognitionId
─────────────────────────────────────
wife              →    wife
gardener          →    gardener
accountant        →    accountant
painter           →    painter
baseline          →    zhaoying (玩家自身)
```

**切换效果**:
- 场景中物体的可见性/材质随认知层变化
- 夫人层：物件边缘过分整洁，名帖墨迹浮出
- 园丁层：水痕、根系、青苔具有方向，水路闭环
- 账房层：数字与墨迹改变时间状态
- 画师层：笔触替代真实法线，错误透视
- 基准层：逐步撤销前四层覆盖

**切换键**: Tab

### 5.3 空间矛盾机制

**定义** (`SpatialContradiction`):
- 同一物理位置，在不同记忆层中呈现不同空间结构
- 第一章两个矛盾点：`waterline-direction`（水路 vs 墙）、`corridor-count`（7 扇窗 vs 5 扇窗）
- 检视方式：在同一位置切换 Tab，观察变化

**实现** (`LoopController.ts`):
- 检测玩家是否在两个认知层中处于同一位置但看到不同空间
- 矛盾确认后设置 `contradiction.*` 旗标

### 5.4 借景机制（第一章独有）

**引擎**: `BorrowAnchorController.ts` + `BorrowedViewPortal.ts`

**流程**:
```
1. 玩家在认知 A 中找到可借物 (borrowable)
2. 在锚点 A 执行 borrow(objectId, cognitionA, anchorId)
3. 切换至认知 B
4. 在锚点 B 执行 anchor() — 借物出现在 B 的空间中
5. 借物在认知切换时保留（已锚定）
6. 可执行 unanchor() 归还
```

**第一章借景数据** (`vertical-slice-content.ts`):
- `CH1_BORROW_SOURCE`: 借出源（夫人证词中的月洞门）
- `CH1_ANCHOR_TARGET`: 锚定目标（园丁记忆中的位置）
- `CH1_BORROWED_VIEW_POINT`: 借景视角点

**RenderTarget Portal** (`BorrowedViewPortal.ts`):
- 从目标认知层视角渲染场景
- 输出到 RenderTarget
- 投射到借景物体表面
