# 《游园惊梦：四面证词》重构执行协议

Updated: 2026-09-03

本协议只规定**如何执行**，不改变剧情、设计或 Task 内容。剧情事实仍由 V5.0 母剧本决定。

## 1. 每个 TASK 的强制五段流程

任何 TASK 必须按下面顺序闭环，禁止跳步：

1. **提取计划**：完整读取 TASK 的目标、范围、执行内容、交付物、验收、依赖；同时读取母文档相关问题与相关剧情母稿。
2. **思考与制作**：先检查当前 Runtime 的真实实现，再设计修改；保留正确实现，修正冲突实现。不得因为“已有文件”直接判完成。
3. **比对与补全**：回到母文档问题表和剧情母稿逐项反查。若 TASK 漏掉了完成该问题所必需的内容，应在不改变上游事实的前提下补齐；若需要新增剧情文本，停止编码并回母稿处理，不现场续写。
4. **验证**：至少执行静态搜索/结构检查/测试之一；能运行时还要做 typecheck、测试、Runtime walkthrough、截图或录像。若本机环境阻塞，记录 `VERIFY-DEFERRED` 与原始错误，绝不能写“已通过”。
5. **顺序推进**：只有当前 TASK 的工程交付已完成，且可执行验证已做完或明确记录环境阻塞后，才允许提取下一个 TASK。

## 2. 禁止项

- 禁止跳 TASK、跳执行步骤、跳剧情场景、跳母文档问题。
- 禁止把剧情母稿摘要成几张卡片后称“完整接入”。
- 禁止删减 V5 主线对白以追求开发速度。
- 禁止 UI/Runtime 现场拼接新的主线剧情含义。
- 禁止用 Box/Sphere/Cylinder/Capsule 等 primitive 冒充正式人物、证物、家具或关键建筑视觉。
- 禁止因为第三方资产“已下载”就判定 Runtime 已使用。
- 禁止把测试文件存在、组件存在、能编译当成玩家流程完成。
- 禁止为了关闭 QA 问题临时改文案掩盖逻辑/资产/碰撞问题。

## 3. 图片与资产

当 TASK 或母文档要求 CG、页面主视觉、地图、文书图像、证物图像或其他正式图片时：

1. 图片必须有明确剧情/界面用途；
2. 需要生成时应生成正式资产，而不是只保存 prompt；
3. 资产必须进入仓库的正式资源目录和 manifest/台账（如适用）；
4. Runtime 必须实际引用；
5. 视觉验收必须确认没有被旧占位实现覆盖。

## 4. 三层 Source of Truth

1. `../../../游园惊梦_完整剧情母剧本_V5.0.md`（工作区根目录）：剧情事实与完整文本。
2. `../../../游园惊梦_整体重构执行母文档_V1.0.md`：问题、体验原则、最终解决形态。
3. `../../../游园惊梦_重构TASK执行计划_V1.0.md`：实施顺序、任务范围与验收。
4. 旧 Ink、hardcoded StoryLine、bark、UI string、旧 GDD 只能作为现状/历史证据。

> 相对路径说明：本文件位于 `garden-of-shadows-game/docs/restructure/`；三份权威文件位于整个工作区根目录。为避免复制后产生两个可编辑真相源，不在 app 内复制正文，而使用 `SOURCE_VERSIONS.json` 锁定路径与 SHA-256。若未来需要分发 app 子目录，必须由脚本生成只读快照并校验哈希，不手工复制。

## 5. 冲突处理

- 旧代码与 V5 冲突：V5 胜出，旧内容弃用。
- TASK 与母文档发生直接冲突：停止冲突项，记录问题；不自行折中。
- 专项计划与三份核心文档冲突：核心文档优先；专项计划只能提供更具体、且不改变上游要求的实施办法。
- 用户最新明确执行要求只改变执行纪律，不自行改变剧情事实。
