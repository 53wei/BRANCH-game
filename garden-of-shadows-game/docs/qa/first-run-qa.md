# First-run QA｜真正的第一次玩家流程

Updated: 2026-09-02

## 目的

本流程用于 TASK-004 / TASK-024 / TASK-054。任何“序章首次体验已修好”的结论，都必须先从真正的空存档开始，不允许用开发者旧存档、章节跳转或手工删除多个 localStorage key 代替。

## 一键入口

开发环境打开：`/dev/qa`

- **清空正式存档并开始首次流程**：删除本游戏唯一正式存档 key，恢复默认 CampaignSave，并直接进入序章。
- **隔离章节 Smoke**：通过 `?devChapter=<chapterId>` 使用内存 QA 存档启动章节；运行中不会写回正式玩家 localStorage。
- 正式首页不提供上述入口；生产环境 `/dev/qa` 不提供 QA 操作。

## First-run 固定流程

1. 从 `/dev/qa` 点击“清空正式存档并开始首次流程”。
2. 确认首次教程自动出现。
3. 关闭/完成教程后，从园门场景按正式剧情推进。
4. 记录第一次获得自由移动控制的时间。
5. 依次完成：园门 → 前厅画像 → 离家记录 → 西院基线 → 水榭 → 原路返回 → 门消失。
6. 不使用 debug marker、不使用章节跳转、不改 localStorage。
7. 到第一章标题出现时结束本次 first-run 记录。

## 章节 Smoke

在 `/dev/qa` 选择对应章节。Smoke 只用于快速确认：

- Runtime 能启动；
- 关键资产能加载；
- 玩家不会出生在模型/墙体中；
- 主目标存在；
- 基础移动、交互、地图、暂停可用；
- 不污染正式存档。

Smoke **不能替代**正式从前章连续进入的剧情/存档回归。

## 关闭条件

TASK-004 关闭前必须满足：

- 任意开发者不打开浏览器 DevTools，即可在 30 秒内进入真实 first-run；
- 正式首页看不到 QA / Smoke 入口；
- 章节 Smoke 不写回正式 CampaignSave；
- first-run 有固定记录模板，可复现阻塞和耗时。
