### 1.5 章节路由表

项目当前实现 **4 个可玩章节** + **3 个规划章节**，由 `app/page.tsx` 的 `view` 状态驱动：

```
view 值               → 运行时组件                  → chapterId
─────────────────────────────────────────────────────────────────────
"prologue-rain"      → PrologueRuntime             → "prologue-rain"
"west-corridor-loop" → GameRuntime                 → "west-corridor-loop"
"north-tower-ledger" → NorthTowerRuntime           → "north-tower-ledger"
"missing-room"       → MissingRoomRuntime          → "missing-room"
"settings"           → SettingsPanel (page.tsx 内联) → N/A
```

路由组件通过 `React.lazy()` 动态导入，每个运行时接受统一的 props 接口：
```
{ chapter: ChapterManifest; save: CampaignSave; onSave: (save) => void; onExit: () => void; onContinue?: () => void }
```

## 三、运行时代码完整梳理

### 3.1 PrologueRuntime（序章 · ROUTE 01）

**Phase 状态机：**
```
loading → letter → gate → gate-choice → explore → confront → enter → title → complete
                                                     ↓
                                                  error
```

**入口参数：**
- `chapter: ChapterManifest` — 来自 `campaign.ts` 的 `getChapter("prologue-rain")`
- `save: CampaignSave` — 完整存档对象
- `onSave: (save) => void` — 持久化回调（由 page.tsx 的 `persist` 传入）
- `onExit: () => void` — 返回首页
- `onContinue: () => void` — 进入第一章

**初始化流程（boot 函数）：**

1. 检查 `visualTest` 开发参数，支持 3 个审计姿势：`wall-scale`、`door-scale`、`gameplay-camera`
2. 创建渲染器：`createRenderer(canvas, { forceWebGL, quality })`
3. 处理存档位置迁移：检测 V3.0 旧存档在 `MOD_A_LargeTree` 内的浮动出生点
4. 创建物理世界：`PhysicsController.create(spawn, prologueColliders)`，包含 `tingYuXuanLayout.colliders` + `tingYuXuanPrologueColliders`
5. 禁用序章门锁碰撞器：`physics.setColliderEnabled("prologue-gate-lock", false)`
6. 创建 Master 场景：`TingYuXuanScene.create(chapter.memories, quality, renderer.renderer)`
7. 设置摄像机 FOV = 70
8. 创建 `AudioAtmosphere`、`CameraRig`、`InteractionController`
9. 构建序章视觉层（老周剪影、三件证物、异常墙）
10. 注册 3 个证据交互点 + 1 个 NPC 交互点
11. 预编译渲染管线：`renderer.renderer.compileAsync(world.scene, world.camera)`
12. 启动渲染循环

**渲染循环核心逻辑（每帧执行）：**

```
physics.pose() → player position
if playable (explore/enter phase) → WASD 移动
update PlayerAvatar
CameraRig.syncExploration + update
world.update(delta, player, false)
if explore phase → resolvePrologueGuidance → landmarks → anomaly detection
interaction.focus → prompt
render world
telemetry (每 500ms)
```

**Phase 详细行为：**

| Phase | 触发条件 | 玩家可交互 | 关键行为 |
|-------|----------|------------|----------|
| loading | 初始状态 | 否 | 显示加载遮罩 |
| letter | boot 完成 | 否 | 展示死者信纸，SemanticMorphText 变形 "没有回来" |
| gate | 点击"合上信纸" | 否 | 老周与赵映 8 行对白，点击推进 |
| gate-choice | 对白结束 | 否 | 三选一问题，记录 flag |
| explore | 推开院门 | 是 | 自由探索，采集证物，触发 landmarks，触发 anomaly |
| confront | 与老周对话 | 否 | 8 行对白（核心叙事） |
| enter | 从 confront 出来 | 是 | 沿石路走向 ROUTE_02_A_ENTRY |
| title | 到达入口 | 否 | 5 行告别对白 → 标题页 "你没有回来" |
| complete | 标题 settle | 否 | 解锁第一章 |
| error | 异常 | 否 | 显示错误信息 |

| prologue-first-anomaly | [4.15, 0.9, 42.85] | 2.0 | 第一次空间异常触发点 |
| umbrella | [5.4, 0.9, 43.45] | — | 旧伞证物 |
| shoes | [4.55, 0.9, 41.55] | — | 旧鞋证物 |
| ledger | [6.1, 0.9, 41.05] | — | 入园簿证物 |

**序章完成条件（completionFlags）：**

**存档迁移逻辑：**

V3.0 旧存档可能将玩家出生点保存在 `MOD_A_LargeTree` 内的浮动位置。PrologueRuntime 检测以下 4 个坐标范围内的旧存档，将其视为无效并忽略：

### 3.2 GameRuntime（第一章 · ROUTE 02）

**Phase 状态机：**
```
loading → playing → chase → complete
            ↓         ↓
          failed   (loop-broken → playing)
```

**入口参数：**
- `chapter: ChapterManifest` — `getChapter("west-corridor-loop")`
- `save: CampaignSave`
- `onSave: (save) => void`
- `onExit: () => void` — 返回首页
- `onContinue: () => void` — 进入第二章

**初始化流程（boot 函数）：**

1. 创建渲染器
2. 恢复存档位置（support visualAnchorId visual test）
3. 创建物理世界：`PhysicsController.create(spawn, tingYuXuanLayout.colliders)`
4. 创建 Master 场景：`TingYuXuanScene.create(chapter.memories, quality, renderer.renderer)`
5. 构建借景系统：
   - `anchorThresholdStone` — 阈值石锚点（夫人认知中的踏石）
   - `borrowThresholdStone` — 借景触发区域
6. 创建 `CameraRig`（stableCamera 模式平滑时间不同）
7. 创建 `InteractionController`
8. 注册交互点：
   - 4 个矛盾勘验点（waterline-direction, corridor-count 各 2 个记忆版本）
   - 4 个切片证据点（CH1_TRACES × 4）
   - 1 个借景观察点
   - 2 个借景源/锚点
   - 3 个奖励点
   - 追逐失败点
9. 注册 ink 对话序列（7 个）
10. 构建布告栏 bark 系统
11. 设置初始记忆层
12. 启动渲染循环

**渲染循环核心逻辑（每帧执行）：**

```
physics.pose() → player position
if playing → WASD 移动
update PlayerAvatar
CameraRig.syncExploration + update
world.update(delta, player, false)
interaction.focus(world.camera, player) → prompt
if chase active → world.setOwnerVisible + faceless owner AI
if slice inspection → portal render (borrowed view)
dialogue handling (activeDialogue 时暂停移动)
objectives resolution
```

**第一章交互系统详解：**

GameRuntime 是四个运行时中最复杂的，包含 3 层交互系统：

**第一层：矛盾勘验（Contradiction Inspection）**
```typescript
// 每个矛盾有两个交互点（两份证词各一个）
inspectContradiction(id: string, memoryId: string)
// 在 waterline-direction 或 corridor-count 位置
// 按 F 切换当前记忆层，记录 observedBy
```

**第二层：切片证据（Slice Evidence）**
```typescript
inspectSliceEvidence(id: string)
// 4 个 CH1_TRACES 位置：waterline, mud, lantern, plant
// 不需要特定记忆，直接在物理世界勘验
```

**第三层：借景系统（Borrowed View）**

### 3.6 摄像机系统（CameraRig）

**两种模式：**
```
exploration — 第一人称自由观察
investigation — 锁定观察（FOV 缩小到 58，前移偏移 0.18）
```

**参数：**
```
FOV: exploration = 70, investigation = 58
eyeHeight: 0.74
smoothTime: 0.12（默认）
```

**API：**
- `syncExploration(position, yaw, pitch, immediate?)` — 同步到探索模式
- `enterInvestigation(position, yaw, pitch)` — 进入调查模式
- `exitInvestigation(position, yaw, pitch)` — 退出调查模式
- `update(delta)` — 每帧更新（平滑插值）
- `dispose()` — 清理

### 3.7 渲染器适配器（RendererAdapter）

**工厂函数 `createRenderer(canvas, options)`：**
```
options: { forceWebGL: boolean, quality: "high" | "stable" | "low" }
```

**选择逻辑：**
1. 如果 `forceWebGL === true` → 使用 WebGL2Renderer
2. 否则尝试 WebGPURenderer → 失败时回退到 WebGL2Renderer

**质量参数影响：**
- `high` — 完整阴影、高粒子数、高像素比
- `stable` — 降级阴影、中粒子数
- `low` — 无阴影、低粒子数、限制像素比

**暴露接口：**
```
backend: RendererBackend ("webgpu" | "webgl2")
antialias: boolean
shadowsEnabled: boolean
renderer: WebGPURenderer | WebGL2Renderer
resize(width, height, dpr)
dispose()
```

```json
{
  "prebuild": "npm run dialogue:compile && npm run validate:content",
  "build":    "vinext build",

  "build:portable": "pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/release/build-windows-portable.ps1"

```

### 19.2 构建流程

```
1. prebuild:
   a. 编译 ink 脚本 → .json
   b. 运行 vitest 内容验证

2. build (web):
   a. vinext build → Next.js 构建输出
   b. 包含 SSR + RSC

3. build (portable):
   a. vite build (vite.portable.config.ts)
   b. 输出单文件 HTML + 内联资源
   c. 用于 Windows 便携版
```

### 22.3 已知不一致（非缺失，是设计现状）

1. **认知 ID 双重命名：** `"artist"` (types.ts) vs `"painter"` (speakers.ts + 运行时)。运行时统一使用 `"painter"`，`COGNITION_BY_MEMORY` 做了映射。
2. **老周双面角色：** `"gardener"` 和 `"steward"` 在 speakers.ts 中都是"老周"，但名字不同。序章使用 `"steward"`，第一章使用 `"gardener"`。
3. **目标系统两种实现：** 序章使用 `PrologueGuidance` 接口，其他章节使用 `ObjectiveDefinition` 接口。第三章使用内联 `objectiveFor` 函数而非数组。
4. **对话系统三种实现：** 序章用硬编码 StoryLine，第一章用 ink 对话 + bark，第二章/第三章只用 bark。
