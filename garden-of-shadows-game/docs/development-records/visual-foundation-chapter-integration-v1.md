# 《游园惊梦：四面证词》视觉基础与章节整合总览 V1

更新时间：2026-08-28  
对应分支：`codex/visual-foundation-chapters-integration`

## 1. 本轮目标

本轮不是继续增加新章节，而是把三个此前分散的开发方向重新接到同一条生产线上：

1. 以最新 `main` 中的听雨轩正式视觉基础、资产管线与共享地图拓扑为底座。
2. 保留已经完成的第三章《前厅访客》和第四章《水榭密室》的剧情、证据、对话与存档逻辑。
3. 将新视觉计划中的第二章《假山旧路》与现有第二章《北楼暗账》合并，不删除已完成内容。
4. 让第一章至终章使用一条明确、可测试的园林路线，而不是互不关联的独立地图。
5. 明确区分正式视觉、可玩白盒和后续待迁移内容。

## 2. 设计结论

### 2.1 第二章不替换，而是合并

第二章统一命名为《假山旧路》，内容分成两个连续段落：

- 前半段“假山旧路”：学习正常空间基线、认知循环、借景和锚定。
- 后半段“北楼暗账”：沿锚定路线进入北楼，通过时间借景调查账桌、窗框、假山和秘密通道。

这样既满足新计划要求的 Borrow / Anchor 教学，也保留现有北楼剧情和钱先生证词。

### 2.2 全章使用同一座听雨轩

共享路线定义在：

`app/game/manifests/campaign-topology.ts`

当前章节连接如下：

| 章节 | 进入位置 | 章内主要位置 | 离开位置 | 下一章 |
|---|---|---|---|---|
| 第一章·西廊回环 | `west-entry` | `west-courtyard`、`wife-moon-gate` | `rockery-side-route` | 假山旧路 |
| 第二章·假山旧路 | `rockery-side-route` | `north-tower-entry`、`north-court` | `front-hall` | 前厅访客 |
| 第三章·前厅访客 | `front-hall` | `east-pavilion-landmark` | `bridge-approach` | 水榭密室 |
| 第四章·水榭密室 | `bridge-approach` | `water-pavilion-entry`、`pavilion-landmark` | `mirror-threshold` | 镜中我 |
| 终章·镜中我 | `mirror-threshold` | 镜面认知空间 | `front-gate` | 结局 |

路线表已经有自动测试，确保后一章确实连接前一章出口，并确保所用锚点都存在于听雨轩共享拓扑中。

6. 使用一个锚定槽保留借来的石板。
7. 沿锚定路线进入北楼一层。
8. 继续原有《北楼暗账》完整流程。

## 6. 推荐代码结构

下一阶段不要继续让每一章复制一套场景。推荐逐步形成：

```text
TingYuXuanScene
├── SharedArchitecture
├── SharedWeatherAndLighting
├── SharedPhysics
├── ChapterOverlay: WestCorridor
├── ChapterOverlay: RockeryAndNorthTower
├── ChapterOverlay: FrontHall
├── ChapterOverlay: SealedPavilion
└── ChapterOverlay: MirrorSelf
```

每个 Chapter Overlay 只负责：

- 当前章节交互点。
- 记忆可见性与拓扑覆盖。
- 临时碰撞变化。
- 剧情触发器。
- 章节独有室内或异常空间。

共享建筑、灯光、天气、资产加载和园林坐标必须继续留在 `TingYuXuanScene`。

## 7. 测试方式

启动：

```bash
npm run dev
```

主页可直接选择“从头测试第二章”“从头测试第三章”或“从头测试第四章”。

第二章建议测试顺序：

1. 点击“从头测试第二章”。
2. 推进开场剧情。
3. 按 H 定位正常空间观察点。
4. 按 F 记录院墙与水痕。
5. 按 Tab 切到园丁证词。
6. 按 H/F 进入循环路。
7. 切回账房证词，观察月洞门。
8. 借出石板并锚定。
9. 沿路线进入北楼。
10. 继续原有北楼账桌、借景窗、过去假山和证据核对流程。

完整工程检查：

```bash
npm run typecheck
npm run lint
npm test
npm run build
```
