## 学习笔记：这个工程怎么搭起来

### 1. 数据层

`app/game/chapter01.ts` 保存章节内容，包括房间、热点坐标、证据、推断选项和章节输入输出。想改线索文字或热点位置，主要改这个文件。

### 2. 状态与规则层

`app/page.tsx` 保存玩家当前在哪个房间、已经找到哪些证据、是否满足推断门槛、是否完成章节。点击热点后，代码把证据 ID 加入 `found` 列表，再根据这个列表决定房间是否解锁、按钮是否可用。

### 3. 显示层

`app/globals.css` 是基础页面样式，`app/chapter01.css` 是第一章专属场景和界面样式。当前固定场景由 CSS 形状拼出，因此以后换正式图片时不会影响证据和推断逻辑。

### 4. 存档

浏览器把房间、证据和完成状态存进 `localStorage`。刷新页面后读取相同的存档键即可恢复。本章与第二章使用不同键，互不覆盖。

### 5. 章节衔接

章节完成时发送统一事件，并附带输出状态。总游戏以后只负责监听事件和切换章节；每一章内部不需要知道其他章节的全部代码。

### 6. 验收

开发完成后依次检查：页面能打开、代码规范通过、正式构建成功、构建后的页面测试通过。这样可以避免“开发模式能看，但交付版本无法运行”。
