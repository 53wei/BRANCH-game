# 《不死世界》总游戏整合开发记录

> 本文只记录已经真实完成并通过验证的工作。后续继续开发时，以本文和总工程当前代码为准。原始 GDD 未被修改。

## 2026-08-20：第一、二章连接

### 已完成

1. 新建总游戏工程 `undying-world-game`，保留原来的 `game-chapter-01` 和 `game-chapter-02`，没有覆盖两个独立章节工程。
2. 把第一章“第七席”和第二章“谁删了名字”迁入同一个游戏壳。
3. 抽出公共 `ChapterRunner`：房间切换、热点调查、证据收集、证据案簿、推断和结算不再在每章复制。
4. 两章分别保留自己的章节数据：房间、证据、推断选项、输入状态和输出状态。
5. 第一章完成后写入 `chapter01.woman_belonged_to_family`，第二章把它作为进入条件；未得到该状态时第二章不可进入。
6. 第一章结算页的“进入下一章”改为总游戏内部切换，不访问外部网址、不刷新页面。
7. 建立唯一总存档 `undying-world.game.save.v1`，保存当前章节、全局状态、各章房间、证据和完成状态。
8. 支持读取旧的第一章、第二章独立本地存档并迁移到总存档；迁移后只继续写总存档。
9. 完成状态单调保存：从结算页返回调查不会把已完成章节改回未完成。
10. 增加“章节总览”“重玩本章”和“重置整个游戏”的入口。

### 章节接口

```text
第一章完成
  └─ 输出 chapter01.woman_belonged_to_family
       └─ 总游戏写入 flags 并解锁第二章
            └─ 第二章读取同名 inputFlag
```

完成事件统一为：

```ts
{
  chapterId: string;
  outputFlag: string;
  evidence: string[];
}
```

事件用于兼容其他模块监听；总存档才是刷新后恢复状态的事实来源。

### 验收结果

- 总工程生产构建通过。
- 第一章 `outputFlag` 与第二章 `inputFlag` 精确匹配。
- 总存档键、统一完成事件、无第二章外链、构建页面包含两个章节的自动化测试通过。
- 原始 GDD 未修改；本次没有上传或发布代码。

### 后续接第三章时的完成标准

1. 第三章使用同一个 `ChapterDefinition` 和 `ChapterRunner`，不复制整套页面。
2. 第三章输入状态必须等于第二章输出状态 `chapter02.first_family_conflict`。
3. 第二章完成后由总游戏内部切换到第三章。
4. 刷新页面后仍停留在正确章节，已经解锁的章节不能重新上锁。
5. 更新本文，并补充第三章链路测试。

### 给开发者的简要理解

现在可以把总游戏理解成“管理器 + 通用播放器 + 章节数据”。`page.tsx` 是管理器，负责顺序、门锁和存档；`ChapterRunner.tsx` 是通用播放器，负责玩法；每个 `chapterXX.ts` 像一张章节配置表。以后增加章节，主要是新增配置和场景，而不是再复制一个完整网站。

## 2026-08-20：章节改为 PPT 式播放

### 已完成

1. 将公共章节播放器从上下滚动的调查网页改成固定单屏幻灯片。
2. 每个房间现在是一幕 PPT：左侧显示场景，右侧直接显示三个调查选项。
3. 点击选项后，结果在当前幻灯片中显示，不跳网页、不向下滚动。
4. 底部加入上一幕、播放下一幕、场景页码、证据编号和最终推断入口。
5. 支持左右方向键切换幻灯片，数字键 1、2、3 选择当前幕选项。
6. 开场、最终推断和章节结算分别作为独立幻灯片播放。
7. 第一章和第二章共用这套播放器，后续第三章会自动保持同样的 PPT 结构。

### 当前完成标准

- 游戏页面固定在一屏内，浏览器正文不出现上下滚动。
- 每一幕的可选操作在当前 PPT 上直接可见。
- 关键证据未取得时，下一幕按原章节规则锁定。
- 取得足够证据后才能进入最终推断。

## 2026-08-20：修复第一章到第二章的自动切换

4. 第二章入口仍会校验第一章输出标记，不能绕过章节条件。
